# SneakerDrop Frontend

Клієнтська частина веб-додатку каталогу кросівок **SneakerDrop**. Проєкт демонструє підключення до REST API бекенду з обходом політики CORS, використовуючи HTML, CSS та jQuery.

## Технології

- HTML5, CSS3
- jQuery (`$.ajax()`)
- Python `http.server` для локального запуску

## Вимоги

- Python 3.12
- Git

## Запуск проєкту

Проєкт розділено на два незалежні репозиторії: бекенд (API) та фронтенд (клієнт). Для коректної роботи обидва сервери мають працювати одночасно на різних портах.

| Частина   | Адреса                  | Порт |
|-----------|-------------------------|------|
| Бекенд    | `http://localhost:8000` | 8000 |
| Фронтенд  | `http://localhost:3000` | 3000 |

### Етап 1. Запуск бекенду (API)

Без працюючого бекенду фронтенд не отримає дані для відображення.

1. Склонуйте репозиторій і перейдіть на потрібну гілку:

   ```bash
   git clone https://github.com/ArtemkoDi/SneakerDrop.git
   cd SneakerDrop
   git checkout feature/crud-api
   ```

2. Створіть та активуйте віртуальне середовище:

   ```bash
   python -m venv venv

   # Windows
   venv\Scripts\activate

   # macOS / Linux
   source venv/bin/activate
   ```

3. Встановіть залежності:

   ```bash
   pip install -r requirements.txt
   ```

4. Застосуйте міграції:

   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```

5. Запустіть сервер:

   ```bash
   python manage.py runserver
   ```

### Етап 2. Запуск фронтенду

1. Склонуйте цей репозиторій:

   ```bash
   git clone https://github.com/ArtemkoDi/sneakerdrop-frontend.git
   cd sneakerdrop-frontend
   ```

2. Відкрийте **нове вікно термінала** в папці фронтенд-проєкту та запустіть локальний HTTP-сервер:

   ```bash
   python -m http.server 3000
   ```



### Етап 3. Перевірка роботи

1. Відкрийте браузер.
2. Перейдіть за адресою [http://localhost:3000](http://localhost:3000).
3. На сторінці відобразиться каталог кросівок. Дані автоматично завантажуються з локального бекенд-сервера за допомогою методу `$.ajax()`.

## Можливі проблеми

- **Порожня сторінка або помилка в консолі браузера.** Перевірте, що бекенд запущений на порту 8000.
- **Помилка CORS.** Переконайтеся, що ви використовуєте гілку `feature/crud-api`, де налаштовано CORS.

## Структура сторінок
* **`index.html` (Каталог):** публічна головна сторінка. Відображає перелік доступного взуття, брендів, цін і наявних розмірів. Якщо користувач увійшов, у навігації відображається його ім'я та кнопка «Вийти».
* **`login.html` (Сторінка входу):** форма автентифікації (Username + Password). Підтримує параметр повернення `?next=<url>` після успішного входу. Якщо авторизований користувач намагається відкрити цю сторінку, його автоматично перенаправляє на `index.html`.
* **`register.html` (Сторінка реєстрації):** форма створення нового акаунта з валідацією полів, довжини пароля та збігу паролів на стороні клієнта й сервера.
* **`profile.html` (Особистий кабінет):** захищена сторінка. Доступна лише після автентифікації. Якщо неавторизований користувач відкриває сторінку, відбувається редирект: `login.html?next=profile.html`. Відображає облікові дані поточного користувача (username, email) та статус ролі (`is_staff`).

## Архітектура автентифікації (`auth.js`)
* **Збереження стану:** `access_token` та `refresh_token` зберігаються у `localStorage` браузера.
* **Автоматична авторизація запитів:** функція `Auth.authenticatedRequest()` додає заголовок `Authorization: Bearer <access_token>`.
* **Безшовне оновлення токенів (Silent Refresh):** якщо сервер повертає статус `401 Unauthorized` через закінчення терміну дії access-токена, скрипт перехоплює помилку, виконує фоновий запит на `/api/auth/token/refresh/`, оновлює токен у сховищі та автоматично повторює попередній запит без виходу користувача із системи.
* **Logout:** очищення `localStorage` та редирект на сторінку входу.
